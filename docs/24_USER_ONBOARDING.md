# User Onboarding — Version 1 Release Candidate

## 1. What the application does

CPM is an offline-first construction scheduling and project-controls application. Projects, calculations, BOQ data, baselines, progress, risks, resources, reports, and recovery snapshots are stored in the browser on the current device unless the user explicitly exports a portable project file.

## 2. First launch

1. Open the application while connected to the network once.
2. Wait for the message that the application shell is ready for offline use.
3. Review the browser storage status shown in the project library.
4. Install the application from the browser's install control when available.
5. Export important projects regularly even when persistent browser storage is granted.

## 3. Starting a project

The library supports four starting paths:

- **New project** creates a minimal project with explicit start and finish milestones.
- **Commercial building template** includes representative schedule, BOQ, cost, PERT, risk, productivity, and resource data.
- **Linear road works template** includes earthworks, drainage, pavement, markings, and turnover logic.
- **Interior fit-out template** includes design release, procurement, partitions, MEP, finishes, testing, and turnover.
- **Import `.cpmproj`** validates size, structure, schema, checksum, and references before writing to local storage.

The project-creation wizard is not yet complete. Calendar, locale, unit, and precision settings may require adjustment after project creation.

## 4. Core workflow

1. Set project metadata, status date, and calendars.
2. Create or adjust WBS nodes and activities.
3. Add logic relationships and resolve schedule-health findings.
4. Calculate the schedule and inspect critical and near-critical work.
5. Freeze the approved baseline.
6. Enter actual dates, remaining duration, progress, and actual costs.
7. Review Gantt, network, BOQ, EVM, risk, productivity, and resource views.
8. Freeze immutable reports for the relevant project revision.
9. Export a portable project file after meaningful update cycles.

## 5. Saving and recovery

Authoritative changes save automatically. The status indicator shows saving, saved, or failed states. The application keeps:

- command journal entries;
- named snapshots;
- automatic pre-delete snapshots;
- automatic pre-import snapshots;
- automatic pre-update snapshots before a new PWA release is activated;
- corrupt-record quarantine rather than silently deleting damaged data.

Use **Recovery** inside a project to create or restore snapshots. Restoring a snapshot creates another recovery point before replacement.

## 6. Portable project files

A `.cpmproj` file contains the complete Project Schema Version 4 aggregate. Import verifies the original checksum before migration. Schemas 1, 2, 3, and 4 are supported by the migration matrix.

Keep exported files in at least two locations controlled by the project organization. Browser storage must not be treated as the only backup.

## 7. Application updates

Updates are no longer forced. When an update is available:

1. Select **Prepare and install**.
2. The application creates recovery snapshots for all active and archived projects.
3. The new service worker is activated after snapshot creation succeeds.
4. If project data appears incorrect after the update, restore an automatic pre-update snapshot or re-import a previously exported project file.

Rolling back the application executable itself requires redeploying the previous release. Local project recovery is independent of executable rollback.

## 8. Release qualification

The Enterprise workspace includes a release-evidence panel. It distinguishes:

- mapped and partial functional requirements;
- gates not yet run locally;
- authoritative evidence generated by GitHub Actions;
- release-candidate status versus qualified Version 1 status.

Version `1.0.0-rc.1` is a release candidate and must not be represented as fully qualified while mandatory functional blockers remain.
